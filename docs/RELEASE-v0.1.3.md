# LinkLauncher v0.1.3

正式リリース（2026-10-13）。v0.1.2以降のアイコン表示、保存・編集の改善、入力タイムアウト対策をまとめました。

## 変更

- EXE、アプリのショートカット（`.lnk`）、ファイル、フォルダーにWindowsのアイコンを表示します。ショートカットに指定した独自アイコンと矢印表示も反映します。
- 表示する行のアイコンをバックグラウンドで取得し、件数上限付きのメモリキャッシュを使います。Webリンクや取得できないリンクは従来の記号、ネットワーク上のパスは種別の標準アイコンを使います。常時のファイル走査・監視、Webアイコンのネット取得、画像のディスク保存は行いません。
- 引用符・山括弧・環境変数を含むリンク先にも、起動時と同じ正規化を使ってアイコンを取得します。
- 破損データから復旧した後に保存が失敗しても、正常なバックアップを保持します。
- リンク・カテゴリの検証と保存が成功するまで編集画面を閉じず、失敗時は入力内容を保持します。
- カテゴリの参照IDの表記と空白のみの親カテゴリを正規化し、階層表示・編集時の選択を維持します。
- 日本語を含む作業先・出力先でも入力補助モジュールをビルドできます。
- 右＋左の呼び出しで表示処理が応答期限を超えても、受理済みの左クリックを元アプリへ通さないよう判定を統一しました。取消しが先に確定した要求は表示・非表示を行いません。一時的なロック競合後の連続呼び出しとボタン解放の状態更新も改善しました。

既存のショートカット・マウス呼び出し、通常の右クリック・右ドラッグを維持します。右ボタン入力の保留、再送、カーソル移動は追加していません。登録データの形式は変更しません。

## 確認範囲と既知の制約

アイコン・保存・編集の自動試験と、全体レビュー・修正差分の再レビューを実施しました。入力タイムアウトの競合は、実入力を生成しない独立ハーネスで再現・検証しています。dev.12と今回の正式版では実マウス操作を再試験しておらず、全アプリでの動作確認とは扱いません。

右＋左の呼び出しで元メニューが一瞬見えたり、スタートボタン上でごくまれに残ったりする場合があります。遅れて開くメニューを閉じる際に元画面を一瞬活性化してランチャーへ戻すことがあります。独自メニュー全般の抑止やWindowsが拒否する前面化は保証しません。

右ボタンを押した時点で元アプリが実行する処理は、ランチャーの呼び出し時に取り消せません。管理者権限や異なるbitnessのアプリなどでマウス呼び出しを認識できない場合があります。設定で別のマウス操作を選ぶことができ、ショートカットも利用できます。

## 導入と更新

Windows x64と.NET 10 Desktop Runtime（Windows x64）が必要です。ランタイムはZIPに含みません。未導入の場合は[Microsoft公式ページ](https://dotnet.microsoft.com/ja-jp/download/dotnet/10.0)から導入してください。

旧版をタスクトレイの「終了」で閉じ、新しい場所へZIPを展開して `LinkLauncher/LinkLauncher.exe` を起動してください。データは `%APPDATA%\LinkLauncher\library.json` に保存され、引き継がれます。スタートアップを有効にしている場合は、新版の設定で「保存」を押して起動先を更新してください。

ZIPの全ファイルを `LinkLauncher/` にまとめ、ランタイム・診断ログ・ユーザーデータを含めません。Windowsから取得するアイコン画像は同梱しません。独自コード・アイコン・入力補助DLLはMIT Licenseです。同梱の `THIRD_PARTY_NOTICES.md` と `licenses/DOTNET-LICENSE.txt` に第三者ライセンスを記載しています。

確認内容は[検証記録](https://github.com/fnkuroko-design/LinkLauncher/blob/main/docs/VERIFICATION-v0.1.3.md)をご覧ください。
