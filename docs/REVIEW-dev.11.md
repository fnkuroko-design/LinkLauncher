# 全体レビューとdev.11での対応

日付: 2026-10-13。ユーザーの指定により、gpt-6-astra / highのサブエージェントがレビューを担当しました。修正は親エージェントが行い、同じレビュアーが修正差分を再確認しました。

レビュー対象はdev.10完了ソース `59045e7`。C#の保存・復旧・検索・順序・編集・起動・フォーカス・テーマ・非同期アイコン、nativeの状態機械・フック・共有メモリ・メニュー取消、主要試験、build/publish、CI・配布設定を確認しました。XAMLはイベント接続とアイコン表示を中心に確認しました。旧ChordReleaseReceiverと非配布x86 helperは、本体の稼働経路と区別しています。

レビュアーは静的確認のみを行い、ファイル編集、アプリ起動、実行試験、入力生成、Computer Useは行っていません。P0は見つからず、確定指摘は次の5件です。実GUI・デバイス入力・全Shell拡張の網羅確認ではありません。

## 確定指摘と対応

| 優先度 | 問題と具体的条件 | dev.11での対応 |
| --- | --- | --- |
| P1 | 破損本体から正常な.bakを復旧した後、本体をコピーできても置換できないロック下で保存すると、正常な.bakを破損本体で上書きしてから保存が失敗する。再起動で復旧できなくなる。 | 復旧中は既存.bakを上書きしない。失敗時は復旧状態を維持し、本体の保存成功後に通常のバックアップ更新へ戻す。 |
| P2 | 検証はカテゴリIDの大小文字を区別しないが、UIの比較は区別する。参照IDだけ表記が違う子カテゴリが表示されず、編集時に先頭カテゴリが選ばれる。空白のみの親IDも表示されない。 | 読み込み時に参照IDを実カテゴリIDへ統一し、空白の親をnullへ正規化する。ID自体や読み込み元ファイルは変更しない。 |
| P2 | 名前・タグ・メモ等の保存条件を超えても編集画面が先に閉じ、後の検証・保存失敗で入力を失う。InvalidDataExceptionも共通保存処理で捕捉していない。 | モデルと同じ検証を画面内で行い、保存コールバックが成功するまで閉じない。検証・実保存のエラーを画面内に表示して入力を保持する。 |
| P2 | 日本語のcheckout・Visual Studio・出力パスをASCIIバッチに書くため、非ASCII文字が?になりビルドできない。 | バッチにはASCIIの環境変数参照を書き、実パスとバッチパスを子プロセスのUnicode環境変数へ渡す。親のコードページは変更しない。 |
| P3 | 引用符付きパスや環境変数を含むTargetは取り込み・起動可能だが、生Targetを使用するアイコン取得だけが拒否する。 | アイコン要求でもリンク起動と同じNormalizeTargetを使う。登録Targetは書き換えない。 |

主な対象は `LibraryStore.cs`、`Dialogs.cs`、`MainWindow.xaml.cs`、`ShellIconService.cs`、`scripts/Build-InputBridge.ps1`。完成済みdev.10は保持し、版番号をv0.1.3-dev.11へ進めました。

修正差分の再レビューでは、5件が対応済みで、追加の確定不具合は見つからなかったとの結果です。テストの内容と本体Startupを動かさない構成も確認されました。これは未知の不具合がない保証ではありません。

## 未再現の追加確認事項

native入力の75msのSendMessageTimeout中にUIのトグル処理が始まり、期限を超えると、送信側が失敗と判断して入力を通す可能性があるとの指摘があります。実害は未再現のため確定不具合とは分けます。今回は入力フック・タイムアウト・押下解放の処理を変更していません。追加検証は実入力を使わない送受信ハーネスが候補です。

ThemeChecks・EditorDropChecksによるproduction Appの生成も注意点ですが、現在のコードで実害が発生すると断定する指摘ではありません。今回の回帰試験は、起動処理を無効化したApplicationで本体リソースを読み込み、実ユーザーデータ・常駐版・入力フックを操作しない構成で行いました。

検証結果は[dev.11検証記録](VERIFICATION-dev.11.md)を参照してください。
