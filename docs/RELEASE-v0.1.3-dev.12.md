# LinkLauncher v0.1.3-dev.12

右＋左で呼び出す際、表示処理が応答期限を超えると、ランチャーが表示されながら同じ左クリックを元アプリへ通す可能性がありました。表示・非表示の処理を始める前の受理と、送信側の取消しを、要求番号を含む共通の原子的な判定へ変更しました。

- 受理済みなら応答が遅れても呼び出し入力を消費します。応答前に取消しが確定した要求は表示・非表示を行いません。
- 状態の更新が一時的なロック競合で持ち越された場合も、次の入力を処理する同じロック内で先に確定します。連続呼び出しとボタン解放の判断を維持します。
- 通常の右DOWN・移動・UPの保留、再送、カーソル移動は追加していません。呼び出し操作と75msの応答予算を維持します。

受理後に表示処理そのものが失敗した場合も、その入力を元アプリへ再通過させません。警告は既存の処理を使います。実入力の前面表示・元メニューの取消し、および正式版で記載した右DOWN時点の元アプリ操作やまれなスタートボタンのメニュー残留について、今回改善を確認したものではありません。

入力を生成しない独立ハーネスと静的レビューで確認しました。実機操作の確認は未実施です。[検証記録](VERIFICATION-dev.12.md)を参照してください。既存の正式版・開発版・登録データを保持し、GitHubへは公開していません。
