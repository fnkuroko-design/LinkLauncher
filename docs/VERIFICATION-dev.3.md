# LinkLauncher 0.1.0-dev.3 検証記録

日付: 2026-10-07。Windows / .NET 10。dev.1・dev.2のソースタグと配布物は保持。

## 変更

- 検索欄のCaretBrushをテーマの文字色で明示。フォーカス中は空欄の説明文字を隠し、検索枠をアクセント色にする。検索アイコンや余白のクリックでも入力へフォーカスする。
- カテゴリの選択状態に変更通知を追加し、表示対象との同期を行う。すべて・お気に入り・最近使ったリンクへの切替でカテゴリの選択を解除する。カテゴリ追加・親階層移動にも同期する。
- 右ドラッグジェスチャーを廃止。マウス操作を設定から一つ選べる形式へ変更し、ショートカットを維持する。
- 既定はホイールを押しながら右クリック。右を先に押して左クリック、ホイール単発、戻るボタン、進むボタン、マウス無効も選べる。組み合わせは移動せずに2つ目のボタンを押した時点で認識し、長押し待ちは設けない。
- 組み合わせに使う最初のDownを保留し、移動が5pxを超えた場合は元の押下位置から通常ドラッグへ引き渡す。組み合わせずに離した場合はクリックを復元する。既定では右単独のDown/Upに介入しない。
- 旧JSONは登録済みリンク・カテゴリを保持して新しい呼び出し方式へ移行する。旧マウス設定が無効なら無効を保持する。保存時のバックアップとSchemaVersion=1を維持する。
- 常時タイマー、ディスク走査、ネットワーク通信、外部パッケージは追加しない。

- カテゴリ選択から「すべて・お気に入り・最近使ったリンク」へそれぞれ切り替え、カテゴリの強調が消え、一覧の対象と件数が切り替わることを確認。

確認後、exeパス・コマンドライン・PIDが一致する検証専用プロセスのみ終了した。

## 入力の確認範囲

物理マウスによる組み合わせ、ExplorerやCAD等での実ドラッグ、複数DPI環境は未確認。純粋な状態テストやビルド成功は、他アプリの入力復元まで証明するものではない。

単発ボタンを選ぶ場合は、そのボタンの既存の機能を置き換える。組み合わせ方式も最初の押下を保留するため、すべてのアプリで干渉しないとは保証しない。使用アプリに応じて設定を切り替える。

管理者権限など安全に入力を復元できると確認できない対象と自アプリでは認識しない。入力再生の部分失敗では、Downの挿入有無に応じて孤立Upを防ぐ。UIPI拒否をSendInputの戻り値だけで確定したとは扱わない。
