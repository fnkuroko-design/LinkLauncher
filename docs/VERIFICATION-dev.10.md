# v0.1.3-dev.10 検証記録

日付: 2026-10-13。Windows x64 / .NET SDK 10.0.204。

## 変更

- リンク行の固定記号をWindowsのシェルアイコンに置き換える。取得待ち・失敗・Webリンクでは従来の記号を維持する。
- `SHGetFileInfoW`をCOM初期化済みのSTAバックグラウンドスレッドから呼び出し、WPF画像をFreezeしてUIへ渡す。取得したHICONはfinallyでDestroyIconする。入力フック、カーソル、ボタン状態は変更しない。
- 表示された行のLoaded・DataContextChanged・IsVisibleChangedから取得する。仮想化された行の再利用時は要求時のLinkRowに結果を渡し、別の行へ適用しない。
- キャッシュは最大256件、キューは最大64件。同時要求をまとめ、編集・取り込み・終了時に保留中の要求を無効化する。元アプリの入力処理、データ形式、スタートアップ登録を変更しない。
- ネットワーク上の実パスはアイコン取得に渡さず、SHGFI_USEFILEATTRIBUTESでファイル種別・フォルダーを照会する。常時走査・監視やWebアイコンのネット取得は導入しない。

API仕様: [Microsoft SHGetFileInfoW](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shgetfileinfow)。

## 必要最小限の検証

`ShellIconChecks`の7項目が最終実行で成功。

1. Web・相対パスをShellへ渡さない。
2. 遅い取得でも呼び出し元をブロックせず、STA・凍結画像・重複要求の統合・キャッシュ再利用が成立する。
3. 256件を超えるキャッシュを制限し、取得失敗の繰り返しを抑える。
4. 取得中の編集により古い結果が新しいキャッシュへ戻らない。
5. キューを64件に制限し、終了時は遅い取得を待たず、実行中・待機中の呼び出しを完了させる。
6. 実際のEXE、独自アイコンを指定した`.lnk`、テキストファイル、フォルダー、存在しないファイル、利用不能なUNCパスの種別アイコンを取得する。
7. 本体XAMLから抽出したアイコン領域と本体のリソースを使用し、非同期画像更新・代替記号の切り替え・ライト／ダーク表示を画面を開かず確認する。

最初の実アイコン比較はショートカットの矢印を含む全画像一致を要求して失敗した。実画像を確認し、矢印のない上半分で指定アプリアイコンの一致を確認する方法へ修正した。

表示検証の最初の構成では、Dispatcherの処理により通常のApp.Startupが動き、既存常駐への表示通知と検証Applicationの終了につながる設計になっていた。テーマ状態の追加確認でダーク検証が成立していないことを検出した。Applicationの起動処理を無効化した検証専用構成で本体XAMLのリソースを読み込む方式へ修正し、両テーマが実際に適用されたことも確認して再実行した。初期の7/7表示を両テーマの合格とは扱わない。

最終記録は `artifacts/checks/dev10-icons-20261013-010417/test-result-6.txt`。ライト／ダークの描画結果は同フォルダーの `icon-results-6/icons-light.png` と `icons-dark.png`。失敗時の記録も保持する。検証用ショートカット・ファイル・画像は同フォルダー内だけに作成し、配布物へ含めない。

新版本体の実起動、ユーザーの登録データによる一覧・スクロール操作はこの試験には含まない。入力フックを登録するMainWindowは検証で作らず、マウス入力生成・カーソル自動移動・Computer Useは行っていない。Windowsの全ファイル形式・全Shell拡張の網羅確認は行っていない。
